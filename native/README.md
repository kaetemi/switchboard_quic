# The native QUIC shim (`native/sbq`)

`sbq` is a small Rust crate over [quinn](https://github.com/quinn-rs/quinn) 0.11 (quinn-proto, rustls with ring, tokio) that exposes a flat `extern "C"` ABI, for raw QUIC and for WebTransport over HTTP/3 (the HTTP/3 layer is the crate's own). The native stream provider of `switchboard_quic` (`lib/src/native/`) calls it through `dart:ffi`. The crate builds a `cdylib` (what Dart loads) and a `staticlib` (for embedders that link it).

| Path | What |
| --- | --- |
| `sbq/src/lib.rs` | The ABI: constants, `SbqEvent`, `SbqStats` and every `sbq_*` function, with their contracts in doc comments. |
| `sbq/src/ctx.rs` | The runtime, contexts and their event queues, the notifier thread, the handle tables. |
| `sbq/src/config.rs` | TLS (rustls, TLS 1.3 only) and transport configuration, certificate verification, self-signed certificates. |
| `sbq/src/conn.rs`, `sbq/src/stream.rs` | Listeners, connections, streams. |
| `sbq/src/h3.rs`, `sbq/src/h3_tables.rs` | HTTP/3 codecs: varints, frames, SETTINGS, QPACK with the static table and literals, Huffman decoding (the tables extracted from RFC 7541 and RFC 9204). |
| `sbq/src/wt.rs` | WebTransport codecs: the application code mapping, capsules, the exporter context, the Structured Fields of protocol negotiation. |
| `sbq/src/h3conn.rs` | The HTTP/3 layer of an `h3` connection, and the WebTransport sessions on it. |
| `sbq/src/tests.rs`, `sbq/src/tests_wt.rs` | A self test of the ABI through the exported functions (`cargo test`), raw QUIC and WebTransport, the latter also against a client written on raw quinn streams in the test. |
| `sbq/include/sbq.h` | The C header, generated by cbindgen and checked in. |
| `sbq/prebuilt/<os>_<arch>/` | Where prebuilt libraries go (never committed: `sbq/.gitignore` keeps them and `target/` out of git, `sbq/.pubignore` lets them into a published package; see "Releases"). |

Pinned by `Cargo.lock`: quinn 0.11.12, quinn-proto 0.11.19, quinn-udp 0.5.16, rustls 0.23.45, ring 0.17.14, tokio 1.53.2, rcgen 0.14.10, rustls-platform-verifier 0.7.1. No HTTP/3 or WebTransport crate: the layer is the crate's own, with 385 lines of static and Huffman tables.

## How Dart gets the library

`hook/build.dart` (a Dart build hook, `package:hooks` and `package:code_assets`) provides the library as the code asset `package:switchboard_quic/sbq`, which the `@Native` bindings resolve. `dart run`, `dart test` and `dart build cli` run the hook; it

1. uses `sbq/prebuilt/<os>_<arch>/<file>` when that file exists (`linux_x64/libsbq.so`, `linux_arm64/libsbq.so`, `macos_arm64/libsbq.dylib`, `macos_x64/libsbq.dylib`, `windows_x64/sbq.dll`, ...: the `OS` and `Architecture` names of `package:code_assets`), as a release carries them (see "Releases");
2. otherwise, when the target is the host and cargo is found (on `PATH`, else in rustup's default `~/.cargo/bin`, `%USERPROFILE%\.cargo\bin` on Windows), runs `cargo build --release --locked` on `sbq/Cargo.toml` with the target directory `sbq/target/` and uses `sbq/target/release/<file>`; the first build takes about a minute (LTO), later ones only rebuild what changed. When rustc's own host triple is of another architecture than the Dart VM (an x64 Dart SDK under Rosetta 2 on an Apple silicon Mac, or under Windows' emulation on Arm, with an arm64 Rust toolchain), it builds with `--target` set to rustc's host triple with the VM's architecture (`x86_64-apple-darwin`, `x86_64-pc-windows-msvc`; `rustup target add` it) and uses `sbq/target/<triple>/release/<file>`;
3. otherwise fails, naming the prebuilt path it looked for and the ways out (<https://rustup.rs>, `tool/fetch_prebuilt.sh`). It never builds for iOS or Android, and says so: a library for them is built with their SDKs and placed under `sbq/prebuilt/` (see "Platforms").

A library whose header names another format or architecture than the target's, or that the hook cannot read, fails the build, saying which: ELF by class, machine and byte order, Mach-O in either byte order (a universal library passes when it holds a valid slice of the target's architecture), PE through `e_lfanew`, also beyond the first page. Dart 3.13's hooks runner would bundle such a library as it is, and loading it would then fail with the misleading "cannot open shared object file". It is a header check, not a loader: signatures, deployment targets and imports are not checked. The hook prints which of the two it used (`switchboard_quic: native library from ...`, in `.dart_tool/hooks_runner/switchboard_quic/*/stdout.txt`) and writes the same line to `sbq_source.txt` in its output directory.

cargo runs with `--locked`, so `sbq/Cargo.lock` decides the dependencies: after changing `sbq/Cargo.toml`, run a `cargo build` in `sbq/` once to update it (the hook's failure says so). The library is the one cargo reports for that build (`--message-format=json-render-diagnostics`, which leaves rustc's messages on stderr, where a failed build shows them), so that a `build.target` in a cargo configuration cannot leave the hook an old library in `target/release`. The hook's result is cached; it depends on the crate's sources, `Cargo.toml`, `Cargo.lock` and the library it used, so a changed source, a `cargo clean` or a replaced library runs it again (after a build that wrote the library, the hooks runner says "File modified during build. Build must be rerun." and runs the hook once more the next time, which cargo answers without building). A prebuilt library placed after a cargo build is picked up once the cache is cleared (`rm -rf .dart_tool/hooks_runner`; `tool/fetch_prebuilt.sh` clears this package's) or a source of the crate changes: a prebuilt path that does not exist is not declared, since Dart 3.13 would then run the hook on every invocation.

Dart 3.13's hooks runner gives the hook `PATH`, `HOME` and `USERPROFILE` (and a few others) but not `CARGO_HOME`, `RUSTUP_HOME` or `RUSTFLAGS`: the hook looks in `$CARGO_HOME/bin` only when the variable reaches it (a direct invocation), and a Rust toolchain that needs any of them (a rustup install with its own `RUSTUP_HOME`) cannot build here; build the library by hand and place it as a prebuilt. A target other than the host (`dart build cli --target-os` or `--target-arch`, iOS, Android) is served by a matching prebuilt only; the hook never builds for another target than the host.

AOT: `dart build cli` compiles ahead of time and bundles the library (`bundle/bin/<program>`, `bundle/lib/libsbq.so`; on Windows `bundle/bin/<program>.exe` and `bundle/lib/sbq.dll`); ship the bundle directory as a whole. `dart compile exe` runs no build hooks (and refuses entry points under `bin/` of a package with a hook); a program compiled that way loads the library itself, into the process's global namespace, from `$SBQ_LIBRARY`, else from the executable's directory, else from `../lib` next to it. `tool/aot_smoke.sh` checks both.

## Building by hand

```sh
cd native/sbq
cargo build --release            # target/release/libsbq.so (+ libsbq.a)
cargo test                       # ABI self test
cargo clippy --all-targets       # kept warning-free
```

A prebuilt library for a release is the `cargo build --release` output for that target, copied to `sbq/prebuilt/<os>_<arch>/`; the release workflow does that on each platform (see "Releases"). Cross builds go through `--target` with the matching linker and a C compiler for ring (nothing else is native), for example `x86_64-pc-windows-gnu` with MinGW (`CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER=x86_64-w64-mingw32-gcc`; the DLL then imports system DLLs only, `msvcrt.dll` among them), or `aarch64-unknown-linux-gnu` with Debian's `gcc-aarch64-linux-gnu` (`CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc`, and `qemu-aarch64-static -L /usr/aarch64-linux-gnu` as `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_RUNNER` for `cargo test`). The release profile uses LTO, one codegen unit, `panic = "abort"` and strips symbols: the libraries are about 2.4 to 2.8 MB (Linux x86-64 2.75 MB, Linux aarch64 2.36 MB, Windows x86-64 with MinGW 2.49 MB).

After changing the ABI, regenerate the header and the Dart bindings and commit both:

```sh
cd native/sbq && cbindgen --config cbindgen.toml --crate sbq --output include/sbq.h
cd ../.. && dart run ffigen --config ffigen.yaml     # lib/src/native/sbq_bindings.g.dart
```

`ffigen` needs libclang (found under `/usr/lib/llvm-*` on Debian and Ubuntu; set `llvm-path` in `ffigen.yaml` otherwise). Bump `SBQ_ABI_VERSION` when the ABI changes incompatibly; the Dart layer refuses a library with another version. Version 4 added WebTransport (`sbq_connect_wt`, `sbq_wt_request`, `sbq_wt_accept`, `sbq_wt_reject`, `sbq_wt_drain`, the events `WT_REQUEST`, `DRAINING` and `UNI_STREAM`, the close kinds `REFUSED`, `SESSION_RESET`, `H3_LOCAL` and `H3_REMOTE`, the results `SBQ_NO_CODE` and `SBQ_RETRY`, and sessions in every connection call); version 3, the handshake deadline (`handshake_ms`, the last parameter of `sbq_client_config` and `sbq_server_config`); version 2, `sbq_stream_poll_reset`.

## Releases

The release workflow (`.github/workflows/release.yml`, not yet run on GitHub) accepts a tag `v*` or a manual dispatch naming an existing `v...` tag. It pins the tag's commit, runs `cargo test --locked` and `cargo build --release --locked` on each of the five platforms, and stages Actions artifacts. Only after every build succeeds does a job with `contents: write` create or update a draft, attach the exact five libraries and `SHA256SUMS`, and publish. Concurrent runs for a tag are serialized. Failed uploads leave a draft that a rerun can complete; published releases are verified and left unchanged on rerun:

| Asset | Its place under `sbq/prebuilt/` | Built on |
| --- | --- | --- |
| `linux_x64-libsbq.so` | `linux_x64/libsbq.so` | `ubuntu-latest` |
| `linux_arm64-libsbq.so` | `linux_arm64/libsbq.so` | `ubuntu-24.04-arm` |
| `macos_arm64-libsbq.dylib` | `macos_arm64/libsbq.dylib` | `macos-latest` |
| `macos_x64-libsbq.dylib` | `macos_x64/libsbq.dylib` | `macos-15-intel` |
| `windows_x64-sbq.dll` | `windows_x64/sbq.dll` | `windows-latest` (MSVC, the C runtime linked in) |
| `SHA256SUMS` | the SHA-256 of each library, by its place (`<os>_<arch>/<file>`) | |

Release assets cannot carry directories, hence the names `<os>_<arch>-<file>`; `SHA256SUMS` names the layout the hook reads. Without Rust, get the libraries with

```sh
tool/fetch_prebuilt.sh v0.1.0                 # every platform of the release
tool/fetch_prebuilt.sh v0.1.0 macos_arm64     # one
```

which validates `SHA256SUMS` (known paths, hashes and no duplicates), downloads the selected libraries, checks them against it (`sha256sum`, or `shasum` on macOS), and only then replaces each file atomically under `sbq/prebuilt/` (it needs curl or wget; `REPO` or `RELEASE_URL` point it elsewhere). By hand: download `<os>_<arch>-<file>` from the release page, check it against `SHA256SUMS`, and save it as `native/sbq/prebuilt/<os>_<arch>/<file>`. A library must come from the release of the package's own version: the Dart layer refuses another ABI version. The hook itself never downloads anything: a prebuilt library, else cargo, else a clear failure.

* Linux: glibc, no musl. The libraries built here use glibc symbols up to `GLIBC_2.34` (glibc 2.34 or later, Debian 12, Ubuntu 22.04); the release log prints what each Linux library needs.
* macOS: Rust defaults to deployment targets macOS 11 on arm64 and 10.12 on x64; these are not verified minimum versions for the final library and its dependencies. The workflow prints the linked deployment target. No macOS library has been linked here; the expected arm64 signature is the linker's ad-hoc signature. A copy downloaded with a browser carries the quarantine attribute, which macOS may refuse to load (`xattr -d com.apple.quarantine <file>`); curl and wget do not set it.
* Windows: x64, MSVC with `-C target-feature=+crt-static`, so that no Visual C++ redistributable is needed (no memory crosses the ABI to be freed by the other side, so the DLL's own C runtime is safe).

The pub package (`publish_to: none` for now) will ship the libraries under `native/sbq/prebuilt/`: `sbq/.pubignore` replaces `sbq/.gitignore` there for pub, keeping `target/` out and letting `prebuilt/` in, so publishing a version means running `tool/fetch_prebuilt.sh` with its tag first (`dart pub publish --dry-run` lists them). A package that depends on the published package then needs neither Rust nor a download.

Which core commit the package is tested against is `tool/core_commit.txt` (CI checks core out at it, next to the package, for the path dependency `../switchboard`).

## The ABI in brief

* **Calls are synchronous and never wait on the network.** Something that cannot complete now returns `SBQ_WOULD_BLOCK` (0), and an event follows once it may succeed: `READABLE` after a read, `WRITABLE` after a write, `OPENED` after an open without stream credit. `sbq_connect` and `sbq_connect_wt` resolve a name in the runtime; `sbq_listen` takes an IP address literal (a name is `SBQ_ERR_ARG`), since resolving it in the call could block: the Dart provider resolves a listen name first, asynchronously. Every wait lives in Rust (quinn's wakers, tasks on a tokio runtime that owns the UDP sockets, with quinn-udp's GSO/GRO); the caller polls again once per event. Events can be spurious.
* **Events** go to a context (`sbq_init` makes one; the Dart layer makes one per isolate). A context's queue rings its doorbell callback, from one notifier thread, when it goes from empty to non-empty; the embedder then calls `sbq_poll` until it returns fewer events than asked. No thread calls the doorbell while it holds a quinn lock: quinn wakes its wakers with its connection lock held, and calling into Dart there deadlocked against a Dart thread waiting for that lock inside a leaf call. `sbq_shutdown` closes the context's connections and listeners and returns once no doorbell call is in progress (so it must not be a leaf call).
* **Handles** are 64-bit table ids, never pointers, never 0, unique in the process. A connection lives until `sbq_conn_release`, a stream until `sbq_stream_release`; `CLOSED` is reported once per connection.
* **Buffers** passed in are copied before the call returns (writes copy out of the caller's buffer); reads copy into the caller's buffer, and data not read stays in quinn, holding back the peer's flow control credit.
* **Results**: counts and handles are non-negative; `SBQ_FIN` (-1), `SBQ_ERR_*` (-2 to -9), `SBQ_NO_CODE` (-10, a WebTransport reset or stop without an application code) and `SBQ_RETRY` (-11, a finish waiting for a WebTransport stream header) are negative; a result at or below `-SBQ_CODE_BASE` (-16) carries an application error code (`code = -result - 16`), the peer's reset code from a read and the peer's `STOP_SENDING` code from a write or finish. `sbq_last_error` describes the last failure on the calling thread.
* **Resets while nobody reads**: `sbq_stream_poll_reset` tells whether the peer reset the receive direction without reading from it (quinn discards a reset direction's unread data anyway), and otherwise arms the read waker, so that a READABLE follows the next change of the direction (data, FIN or the reset). The Dart layer calls it whenever no read is pending, so that `QuicStream.resetReceived` completes for a reader the layer above has paused.
* **Streams**: release a stream after both directions ended (FIN read, reset received or `sbq_stream_stop`; finish acknowledged, `STOP_SENDING` received, or reset); a direction still open then is aborted as a final safeguard (reset or `STOP_SENDING` with `WT_SESSION_GONE` on WebTransport, 0 on raw QUIC), and a finished send direction keeps its FIN. The shim answers a peer's `STOP_SENDING` with a reset carrying the same code (RFC 9000 section 3.5), which quinn leaves to the application, also on a finished direction whose data is not acknowledged yet. `sbq_stream_set_priority` takes quinn's own levels (strict between levels, round robin within one); the Dart layer maps the provider contract's priority classes onto them (classes 1 and 0 share level 0, class 2 is level 1).
* **TLS**: TLS 1.3 only; ALPN lists in wire form; 0-RTT never (`max_early_data_size` 0 on servers, early data off on clients); no client certificates. A client verifies the server by the platform's trust store (rustls-platform-verifier), by pinned SHA-256 hashes of the certificate DER (compared in constant time), or not at all; the handshake signature is checked in every case. `CLOSED` with `SBQ_CLOSE_CERT_REJECTED` tells a rejected certificate from other handshake failures.
* **Transport**: raw QUIC has bidirectional streams only (`initial_max_streams_uni` 0, no datagram parameter, so a peer cannot open a unidirectional stream without a transport error, and the provider's `incomingUnidirectionalStreams` never delivers one; raw QUIC has no draining signal either, so `draining` never completes); `h3` configurations have HTTP/3's parameters (see "WebTransport over HTTP/3"); per-stream and connection receive windows, idle timeout and keep-alive as configured; the stream limit can be changed at runtime (`sbq_conn_set_max_bidi`). Outgoing connections share one UDP socket per address family, opened on first use and kept for the life of the process (by every context); a listener's socket stays open until it is closed and the connections it accepted have ended. Sockets on an IPv6 address are dual-stack where the platform allows it (`IPV6_V6ONLY` off: quinn does so for its client sockets, the shim for its listeners), so that a listener on `::` takes IPv4 clients on Windows too, whose IPv6 sockets are IPv6-only by default.
* **Handshake deadline**: quinn bounds a handshake only by the idle timeout, so without one a connect to a black hole would wait forever, and a listener would keep a half-open handshake forever. A configuration's `handshake_ms` bounds it in the shim (0: the idle timeout alone). A connect whose attempt (one per address tried; a dual-stack name ends within about the deadline plus 250 ms) does not complete in time ends with CLOSED `SBQ_CLOSE_TIMED_OUT`, as one the idle timeout ended; a listener abandons an incoming handshake not complete in time without announcing it. quinn closes an abandoned attempt and forgets it once the close has drained.

## WebTransport over HTTP/3

A configuration whose ALPN list offers `h3` gives its connections HTTP/3's transport parameters: 16 unidirectional streams for the peer (its control and QPACK streams, and room for the WebTransport and reserved streams this side refuses), and the datagram parameter (`max_datagram_frame_size`, which `H3_DATAGRAM` requires; received datagrams are never read, and quinn drops the oldest beyond 64 KiB); a server grants one more bidirectional stream than `max_bidi`, for a session's CONNECT stream. Raw QUIC keeps its own parameters (no unidirectional stream, no datagram).

* **Client**: `sbq_connect_wt` dials, waits for the server's SETTINGS (a server without WebTransport, or without extended CONNECT, gets the connection closed with `WT_REQUIREMENTS_NOT_MET`), sends the extended CONNECT (`:protocol webtransport`, `:authority`, `:path`, an optional `origin`, `sec-webtransport-http3-draft02: 1`, `WT-Available-Protocols`), and reads the response: a 2xx posts CONNECTED (the protocol of `WT-Protocol`, none without it; one that was not offered closes the session with `WT_ALPN_ERROR`, CLOSED `SBQ_CLOSE_OTHER`), any other status CLOSED `SBQ_CLOSE_REFUSED` with the status in `b` and in the reason (`HTTP status 404`). Interim 1xx responses are skipped. The session has its QUIC connection to itself.
* **Server**: a listener whose ALPN list offers `h3` runs HTTP/3 on the connections that negotiate it (others stay raw QUIC with INCOMING). An extended CONNECT for `webtransport` is held until the client's SETTINGS have arrived (the draft requires it), then posted as WT_REQUEST with a pending session handle (`a` the listener, `b` the draft version: 2 when the client sent the draft-02 header or only draft-02 settings, else 7); the embedder reads `:authority`, `:path`, `Origin` and the protocols offered with `sbq_wt_request`, and answers with `sbq_wt_accept` (the protocol to select, one the client offered, or none) or `sbq_wt_reject` (300 to 599). A request not answered within the listener's handshake deadline (10 s without one) is refused 503, and CLOSED (`SBQ_CLOSE_REFUSED`, 503) tells the embedder. After `sbq_listener_close`, requests on the connections still open are answered 503. Any other request gets 404 and its stream finished; a malformed one is reset with `H3_MESSAGE_ERROR`. Up to 16 sessions per connection (advertised as `SETTINGS_WEBTRANSPORT_MAX_SESSIONS`); more are reset with `H3_REQUEST_REJECTED`. A connection without a session for the handshake deadline is closed.
* **Sessions** are handles in the connection table: `sbq_stream_open`, `sbq_conn_close`, `sbq_conn_release`, `sbq_conn_exporter`, `sbq_conn_protocol`, `sbq_conn_remote`, `sbq_conn_peer_cert_sha256`, `sbq_conn_stats`, `sbq_conn_set_max_bidi` and `sbq_conn_close_reason` take them. A stream the embedder opens carries the session's header (`0x41` and the session ID), written ahead of its first byte or its FIN (`sbq_stream_finish` returns `SBQ_RETRY` while the header waits for credit); the headers of the peer's streams (`0x41`, and `0x54` for unidirectional ones, which arrive as UNI_STREAM) are read and stripped before STREAM. Stream codes are WebTransport application codes (u32), mapped into the HTTP/3 space on the wire (`0x52e4a40fa8db + n + floor(n / 0x1e)`); a peer's code outside that range is `SBQ_NO_CODE` from a read or write and -1 in STOPPED. The exporter is the draft's: label `EXPORTER-WebTransport`, context `session ID (u64 big endian) || len8 label || label || len8 context || context`.
* **Ends**: `sbq_conn_close` sends `WT_CLOSE_SESSION` (the code, u32, and the reason cut to 1024 bytes at a character boundary) and FIN, and posts CLOSED (`APP_LOCAL`) once the capsule and FIN are acknowledged, or the close wait (three round trips, 0.2 to 2 s) passed without that, so that an embedder that tears down its context on CLOSED does not cut the close short; application I/O on the session fails at once; its streams are reset and stopped with `WT_SESSION_GONE` at the same point, so that the peer learns of the close before it sees the resets. The peer's `WT_CLOSE_SESSION` gives CLOSED `APP_REMOTE` with its code and reason, a FIN of the CONNECT stream without one `APP_REMOTE` with code 0; a reset CONNECT stream gives `SBQ_CLOSE_SESSION_RESET`, the QUIC connection closing `SBQ_CLOSE_H3_REMOTE` or `SBQ_CLOSE_H3_LOCAL` (or the QUIC kinds: timeout, transport error, stateless reset); those are all losses. `WT_DRAIN_SESSION` (`sbq_wt_drain` sends it) and an HTTP/3 `GOAWAY` post DRAINING. Once its last session has ended, the QUIC connection is closed (`H3_NO_ERROR`), as the draft advises, after the session's close: by a client once the CONNECT stream has been closed by both sides, or three round trips (0.2 to 2 s) after the session's end; by a server only after those three round trips, the close being the client's until then. Chrome reports a session closed only after it has sent its FIN in answer, and a connection close that arrives before that report fails the session (the page sees "Connection lost." whatever the close said); it closes the connection itself once it has reported the close.
* **Versions**: draft-02 (Chrome 149: `SETTINGS_ENABLE_WEBTRANSPORT` 0x2b603742, `H3_DATAGRAM` as 0x33 and the older 0xffd277, the request header `sec-webtransport-http3-draft02: 1` and the response header `sec-webtransport-http3-draft: draft02`) and draft-07 (web-transport-quinn 0.13.2: `SETTINGS_WEBTRANSPORT_MAX_SESSIONS` 0xc671706a), both with `:protocol webtransport` and the `WT-Available-Protocols` / `WT-Protocol` headers of draft-13 and later (Structured Field strings). The shim advertises both, sends both, and answers a client in its version. The later drafts' signalling (`SETTINGS_WT_ENABLED`, `webtransport-h3`) needs `RESET_STREAM_AT`, which quinn 0.11 lacks, so the shim does not offer it; nor does it send the session flow control settings (`SETTINGS_WT_INITIAL_MAX_*`), so flow control is never enabled and flow control capsules are ignored, as the drafts require then.
* **Bounds**: what a peer can make the shim hold is bounded: a field section of 16 KiB encoded and 16 KiB decoded (counted as RFC 9114 does), a SETTINGS frame of 4 KiB and 256 settings, the payloads of the frames it buffers (a varint for GOAWAY, MAX_PUSH_ID and CANCEL_PUSH; a close capsule's 4 + 1024 bytes), 64 KiB of unknown frames before a request's HEADERS and of frames before a final response (including interim responses and a minimum two-byte framing cost per frame), 16 live or outstanding unreleased session handles per connection, 16 streams held per connection for a session that does not exist yet (each for the handshake deadline, then refused with `WT_BUFFERED_STREAM_REJECTED`; beyond 16 at once), and the handshake deadline for a WebTransport stream's header after its type. The type of a peer's unidirectional stream has no deadline: a peer sends it when it pleases (quiche, Chrome's stack, sends the type of a QPACK stream with its first instruction, and the stream it opens after opens that one with it, typeless), and stopping a peer's QPACK stream ends the connection (Chrome then closes it, "STOP_SENDING received for QPACK send stream"); a typeless stream holds one of the 16 unidirectional streams the peer is granted until the connection ends. The HTTP/3 exchanges always have a deadline, the configuration's handshake deadline or 10 s when it is zero: a client's SETTINGS and response, a server's request headers, the client's SETTINGS before a request is processed, and the embedder's answer. Protocol offers outside the ABI's 1 to 255 bytes are refused with 400. Unknown frames, settings, capsules and unidirectional stream types are skipped without buffering; GREASE is ignored. The dynamic table is refused (`QPACK_MAX_TABLE_CAPACITY` 0, `QPACK_BLOCKED_STREAMS` 0): a field section that needs it closes the connection with `QPACK_DECOMPRESSION_FAILED`, an encoder stream that inserts with `QPACK_ENCODER_STREAM_ERROR`. Protocol violations close the connection with their HTTP/3 code (`H3_MISSING_SETTINGS`, `H3_SETTINGS_ERROR`, `H3_FRAME_UNEXPECTED`, `H3_FRAME_ERROR`, `H3_STREAM_CREATION_ERROR`, `H3_CLOSED_CRITICAL_STREAM`, `H3_ID_ERROR`, `H3_EXCESSIVE_LOAD`).
* **Not done**: datagrams (dropped), `RESET_STREAM_AT` (a reset can lose a stream's header with its data, so the peer cannot tell which session the reset stream belonged to; quinn drops what it buffered of a stream once its reset arrives, so the shim loses the header of a peer's stream reset before it read it, even one that arrived first; web-transport-quinn and Chrome share the limit), session flow control, server push, requests other than WebTransport's (404).
* **Trace**: with `SBQ_TRACE=1` the shim writes the peer's SETTINGS, the requests and responses it decodes, and the stream types and capsules it ignores to stderr.

* **The layer's own streams**: every stream the HTTP/3 layer holds (control, QPACK, request and CONNECT streams, streams held for a session) is in a guard that stops or resets it explicitly when it is given up, a task cancelled at an await included, so that quinn's implicit drop (FIN, `STOP_SENDING` 0) never speaks for it; a FIN once sent is not reset. A closing session's writer and reader are cancelled at the close wait even while other sessions keep the connection up. The server tells a stream of a session that is gone from one of a session still to come without keeping a history: QUIC hands over the peer's streams in ID order, so an ID at or below the last one handed over that is neither a session nor still being classified can never become one.
